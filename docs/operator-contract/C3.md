# C3 — 独立 Node.js Operator 启动并收集 run

**结论：C3 通过。** 一个不共享 Hermes / Python adapter 代码的 Node.js 客户端，自己启动了一个 1 peer × 1 generation run，并用同一套 contract 产出与 Python adapter 一致的证据。

## 客户端

- `node_operator.js` — 独立实现，只用 Node 标准库
- 支持 `validate`、`run`、`status`、`collect`
- 不 import Python adapter，不依赖 Hermes 会话

## 命令

```bash
node node_operator.js --operator node-operator validate /home/andyl/PraxistExamples/praxist_bo_c2

node node_operator.js --operator node-operator run \
  /home/andyl/PraxistExamples/praxist_bo_c2 \
  --config operator_config.json

node node_operator.js --operator node-operator status run_c3_1 \
  --task-project /home/andyl/PraxistExamples/praxist_bo_c2

node node_operator.js --operator node-operator collect run_c3_1 \
  --task-project /home/andyl/PraxistExamples/praxist_bo_c2 \
  --out evidence/
```

## 结果

```text
run:          run_c3_1
exit_code:    0
generations:  1
best metric:  1.881592
artifacts:    22
```

### 与 Python adapter 的一致性

| 检查 | 结果 |
|---|---|
| validate hashes | ✅ 相同 |
| status semantics | ✅ 相同 |
| best metric | ✅ 1.881592 |
| evidence artifacts | ✅ 22 vs 22，哈希相同 |
| 内容差异 | 0（除 operator 字段） |

## 证明了什么

- 两种**不同语言/不同实现**的 Operator 可以驱动同一个 task project；
- 它们对 task/evaluator 的哈希、run 状态、best metric、证据内容判断一致；
- Node 客户端可以独立 launch 新 run，不是只消费旧 run；
- task project 已去掉绝对路径，`validate.paths` 为 pass。

## 还没证明什么

- C3 仍是在同一台机器、同一个 engine 安装、同一个 model provider 上完成的；
- 不是“跨机器”或“跨 provider”无损；
- C4 完整 RSI（多模块 candidate、held-out、promotion evidence）还没做。

所以现在可以说：

> **PRAXIST operator contract 已经通过 C1/C2/C3：Python adapter 和独立 Node.js client 都能启动、查询、收集同一任务，并产出同结构证据。**

但不能说“所有 Agent 在任何环境下都无损”；那是 C4 及跨环境验证之后的事。
